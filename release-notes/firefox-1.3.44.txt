1) RELEASE NOTES  ("What's new in this version?")
----------------------------------------------------------------
New: a keyboard shortcut that shows or hides the screenshot tool
on any website. Press Ctrl+Shift+X and the screenshot panel
appears; press it again and it goes away. Previously the only way
to open it was through the toolbar popup. The shortcut is handled
by the browser, so it works on any page without opening the
popup. You can change or clear it in the Add-ons Manager under
"Manage Extension Shortcuts". The Customize page now shows which
shortcut is currently bound and explains what it does.

Fixed: selecting an area for a screenshot failed in three ways
that all looked identical to the tool being broken.

  - If you released the mouse button over the screenshot panel
    itself, or outside the browser window, the selection never
    finished and the capture overlay stayed on screen until you
    pressed Escape. The panel sits above the overlay, so it was
    swallowing the mouse release. Releasing the button anywhere
    now completes the selection.

  - The panel could intercept a drag that passed over it. It is
    now click-through while you are selecting an area.

  - A click that did not move far enough to be a box was thrown
    away in silence. The overlay just vanished and nothing was
    captured, with no message saying why. It now tells you that
    nothing was selected and to drag a box around the question.

Fixed: on a multiple-choice question answered from a screenshot,
the extension could select a wrong option that the AI had named
only in order to rule it out. If the answer came back as "Oil -
acrylic paint was not invented until the twentieth century", the
option "Acrylic" was selected instead of "Oil", because the whole
explanation was being compared against the answer choices. The
better the explanation, the more likely it was to lose the mark.
Only the answer itself is now compared against the options.

Fixed: when the add-on updates while a quiz page is already open,
the tools used to stop working with no explanation - the
screenshot panel and its selection overlay disappeared mid-use,
and the solver buttons stayed on the page but did nothing when
clicked. A page open at the moment of an update can no longer
reach the add-on at all, which is normal, but nothing said so.
A small notice now appears explaining that Answerly was updated,
with a button to reload the page. It can be dismissed and stays
dismissed.

New: a question-mark button in the extension header opens a help
page answering the questions we are asked most often - which
questions need the screenshot tool, turning features on before a
quiz starts, how the keyboard shortcuts work, which question
types cannot be filled in automatically, and how monthly code
renewal works.

2) NOTES FOR REVIEWERS
----------------------------------------------------------------
Scope of this update, measured against 1.3.43:

1. manifest.json
   - version 1.3.43 -> 1.3.44
   - Added a "commands" entry: one command, "toggle-screenshot",
     suggested key Ctrl+Shift+X. No new permissions. The
     permission list and host permissions are unchanged from the
     previously reviewed version.

2. background/background.js
   - Added a chrome.commands.onCommand listener for that one
     command. It flips the same stored flag the toolbar button
     already flips, injects the existing content/screenshotTool.js
     into the active tab, and sends the same messages the popup
     sends. It does nothing when the user is not signed in.
   - The listener is registered at the end of the file and is
     guarded by "if (chrome.commands?.onCommand)". This is
     deliberate: an unguarded reference throws at the top level
     wherever the API is absent, which would prevent every
     listener below it from registering.
   - It ignores repeat firings within 400ms, so holding the key
     down cannot toggle the panel more than once.

3. content/screenshotTool.js
   - The area-selection overlay now listens for mousemove and
     mouseup on window during a drag instead of only on the
     overlay element, so a release outside the overlay still
     completes the selection. All listeners are removed when the
     overlay closes.
   - The panel is given pointer-events:none while the overlay is
     open so it cannot intercept the drag, and the class is
     removed afterwards.
   - A selection smaller than 10x10 now shows a message instead
     of cancelling silently. Escape still cancels without one.
   - No change to what is captured, how it is cropped, or where
     it is sent.

4. content/quizSolver.js, content/newQuizSolver.js
   - Added answerHeadline(), which returns the leading bold span
     of a model answer, or its first line, and otherwise returns
     the string unchanged. Option matching for screenshot-answered
     questions now compares that instead of the full answer text,
     so an option named inside the explanation is no longer
     selected. The full text is still used unchanged for essay and
     text-input answers. Same change in both quiz engines.

5. content/screenshotTool.js, quizSolver.js, newQuizSolver.js
   - Added answerlyContextLost() and showAnswerlyReloadNotice().
     When chrome.runtime.id is gone the page can no longer reach
     the add-on, so instead of tearing the UI down silently (or
     leaving dead buttons) a notice is appended to the page
     explaining the update and offering location.reload(). It is
     built with DOM methods and inline styles, since no stylesheet
     can be injected at that point, and uses no extension API.
     Dismissal is recorded as a data attribute on <html> so the
     three scripts agree and the periodic re-check cannot re-raise
     it.

6. popup/popup.html, popup.css, popup.js
   - Added a help button in the header and a static help view
     containing the text in section 1. The view is plain markup
     with no remote content. Its two buttons open a YouTube
     tutorial URL and the project Discord invite in a new tab.

7. popup/customize.html, customize.js
   - Added a read-only section that displays the currently bound
     shortcut, read via chrome.commands.getAll(), and explains
     where to change it. It captures no keystrokes.

No new permissions, no new hosts, no remote code, and no change
to the network endpoints the extension talks to. All added code
is in the files listed above.
