1) RELEASE NOTES  ("What's new in this version?")
----------------------------------------------------------------
Changed: on New Quizzes the buttons now sit at the top of each
question, next to the question type and point value, instead of
being pinned to the far right edge. This matches where they have
always appeared on classic quizzes. Applies to every mode -
normal, quiz stealth and screenshot stealth.

Fixed: answer options that differ only by capital letters were
not told apart, so the first one was always chosen. Genetics
questions were the worst affected - options of AA, Aa and aa all
looked identical to the matcher, so every Punnett square question
picked the first one no matter what the answer was. The same
applied to music intervals (M3 and m3), chemistry (Co and CO) and
units (mS and ms). These are now matched exactly.

Fixed: on a multiple-choice question answered from a screenshot,
the extension could select a wrong option that the answer had
named only in order to rule it out. If the answer came back as
"Oil - acrylic paint was not invented until the twentieth
century", the option "Acrylic" was selected instead of "Oil",
because the whole explanation was being compared against the
answer choices. Only the answer itself is now compared.

New: questions that ask you to listen to audio are now declined
instead of guessed. Answerly cannot hear, so on questions like
"click the play button and identify the chord" it was answering
at roughly the accuracy of a coin toss and presenting that as an
answer. It now says it cannot hear the question and leaves it to
you, which also saves the solve.

Fixed: selecting an area for a screenshot failed in three ways
that all looked like the tool being broken. Releasing the mouse
over the screenshot panel, or outside the window, left the
selection unfinished and the capture overlay stuck on screen. The
panel could intercept a drag passing over it. And a click too
small to be a box was discarded in silence. Releasing anywhere
now completes the selection, the panel is click-through while
selecting, and a too-small selection says so.

Fixed: when the add-on updates while a quiz page is already open,
the tools used to stop working with no explanation - the
screenshot panel disappeared mid-use and the solver buttons did
nothing when clicked. A page open at the moment of an update
cannot reach the add-on, which is normal, but nothing said so. A
notice now explains it and offers to reload the page.

New: a keyboard shortcut that shows or hides the screenshot tool
on any website. Press Ctrl+Shift+X and the panel appears; press
it again and it goes away. The shortcut is handled by the
browser, so it works without opening the popup. Change or clear
it in the Add-ons Manager under "Manage Extension Shortcuts".

New: a question-mark button in the extension header opens a help
page answering the questions we are asked most often - which
questions need the screenshot tool, turning features on before a
quiz starts, how the keyboard shortcuts work, which question
types cannot be filled in automatically, and how monthly code
renewal works.

Fixed: on some quiz layouts every graded question was recorded as
wrong when the results page was read, even on attempts that
scored well. This only affected the add-on's own internal
accuracy records, never a student's grade or anything shown to
them.

2) NOTES FOR REVIEWERS
----------------------------------------------------------------
Scope of this update, measured against 1.3.43. No new
permissions, no new hosts, no remote code, and no change to the
network endpoints the extension talks to.

1. manifest.json
   - version -> 1.3.46
   - Added a "commands" entry: one command, "toggle-screenshot",
     suggested key Ctrl+Shift+X. The permission list and host
     permissions are unchanged from the previously reviewed
     version.

2. content/newQuizSolver.js (button placement)
   - placeNQButton() now looks for the question's header row and
     appends the button inline there, so it lands beside the
     point value rather than pinned to the right edge. The row is
     found by three independent routes (sdk-position-box-text or
     sdk-interaction-type-name-div and their row; a short leading
     block containing a point value; a short non-question first
     block), because native New Quizzes renders no sdk-* type
     label at all. If none match, the previous absolutely
     positioned corner is still used, so the button can never end
     up missing. The button sets pointer-events:auto because the
     stylesheet disables them on the header, and margin-right:auto
     so a space-between header cannot throw it to the right.

3. background/background.js
   - Added a chrome.commands.onCommand listener for that one
     command. It flips the same stored flag the toolbar button
     already flips, injects the existing content/screenshotTool.js
     into the active tab, and sends the same messages the popup
     sends. It does nothing when the user is not signed in.
   - The listener is registered at the end of the file and is
     guarded by "if (chrome.commands?.onCommand)", so its absence
     cannot stop the listeners below it registering.
   - Repeat firings within 400ms are ignored, so holding the key
     cannot toggle the panel more than once.

4. content/screenshotTool.js
   - The area-selection overlay listens for mousemove and mouseup
     on window during a drag instead of only on the overlay
     element, so a release outside the overlay still completes the
     selection. All listeners are removed when the overlay closes.
   - The panel is pointer-events:none while the overlay is open so
     it cannot intercept the drag.
   - A selection smaller than 10x10 shows a message instead of
     cancelling silently. Escape still cancels without one.
   - No change to what is captured, how it is cropped, or where it
     is sent.

5. content/quizSolver.js, content/newQuizSolver.js (answer text)
   - Added answerHeadline(), which returns the leading bold span
     of a model answer, or its first line, and otherwise returns
     the string unchanged. Option matching for screenshot-answered
     questions compares that instead of the full answer text, so
     an option named inside the explanation is no longer selected.
     The full text is still used for essay and text-input answers.

6. content/quizSolver.js, content/newQuizSolver.js (matching)
   - matchOptionIndex() / matchNQOptionIndex() try a
     case-sensitive exact match against the option labels before
     the existing normalised comparison. The normaliser
     lowercases, which made AA / Aa / aa indistinguishable and
     selected the first of them every time; likewise M3 vs m3, Co
     vs CO, mS vs ms. Strictly additive - an exact case-sensitive
     hit cannot be the wrong option, and anything that does not
     hit falls through to the previous behaviour.

7. content/quizSolver.js, content/newQuizSolver.js (audio)
   - Added questionNeedsHearing() / nqNeedsHearing(), matching an
     <audio> element or an instruction to listen ("click the play
     button", "listen to the", "what you heard"). Such questions
     are declined with their own notice rather than answered, in
     both the per-question button and the Solve All pass. The
     pattern matches instructions to listen, not the topic of
     sound, so ordinary text questions about audio are unaffected.

8. content/screenshotTool.js, quizSolver.js, newQuizSolver.js
   - Added answerlyContextLost() and showAnswerlyReloadNotice().
     When chrome.runtime.id is gone the page can no longer reach
     the add-on, so instead of tearing the UI down silently a
     notice is appended to the page explaining the update and
     offering location.reload(). It is built with DOM methods and
     inline styles, since no stylesheet can be injected at that
     point, and uses no extension API. Dismissal is recorded as a
     data attribute on <html> so the three scripts agree.

9. content/scoreReporter.js
   - verdictFor() no longer applies New Quizzes heuristics to
     Classic markup. Classic prints the words "Incorrect answer"
     beside every distractor it lists, so a text test intended for
     New Quizzes matched every question and recorded whole
     attempts as wrong. Classic is resolved by its own class names
     above; if those do not settle it the function returns null
     (unknown) rather than guessing. Affects only the add-on's
     internal records.

10. popup/popup.html, popup.css, popup.js
   - Added a help button in the header and a static help view
     containing the text in section 1. The view is plain markup
     with no remote content. Its two buttons open a YouTube
     tutorial URL and the project Discord invite in a new tab.

11. popup/customize.html, customize.js
   - Added a read-only section that displays the currently bound
     shortcut, read via chrome.commands.getAll(), and explains
     where to change it. It captures no keystrokes.
